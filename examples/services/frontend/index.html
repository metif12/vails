Vails Services Demo

Seven services, one window: clipboard, opener, notification, menu, dialog, tray and os_info. Wave 3 of Phase 5 S1 added menu and tray (ADR-0017); wave 4 added the window menu bar, the tray menu and the GTK dialogs (ADR-0023, ADR-0026, ADR-0027).

Clipboard

A round trip needs no human — and the text is non-ASCII on purpose, because the Windows path is UTF-8 → UTF-16 → clipboard → UTF-8.

Notification

is_supported first, so the page never fires a notification that quietly does nothing. Windows shows a real WinRT toast, attributed to this app's bundle.identifier; other platforms report the stub. notify resolves with the mechanism that ran, so the status line below is the proof.

Opener

open_url takes http, https, mailto, tel only; open_path a local path. with (an app override) is Windows-only.

Menu

A native popup, parented to nothing and owned by the window. The choice comes back as an menu:clicked event — never as the command's result — so one contract serves Windows' modal TrackPopupMenuEx and Linux' immediate GtkMenu. The same button installs the window's menu bar, which is not modal at all and answers on the same event.

Dialog service

Native file, save and message dialogs. All three are blocking: true in the manifest, which is the ADR-0014 exception: a modal dialog runs a nested loop, so the calling thread parks until the user answers. A canceled result is a normal answer, not an error — only a genuine failure rejects.

Tray

An icon in the notification area, installed with tray.set. Clicks are OS-initiated messages that reach V through the window host seam (a comctl32 subclass) and arrive as tray:clicked. tray.set_menu attaches a menu to the icon instead: a right click then opens that menu and the choice arrives as menu:clicked — the same event every other menu in Vails uses.

main-thread post (U0)

A worker computes a result and hands it to the window thread, which runs it and emits to the page. Before U0 the worker dropped the result on the floor, because ctx.emit ends in webview_eval on a thread the webview object does not own.

The proof is started from the V side (VAILS_SERVICES_PROBE=post), not from this button: a worker is spawned in on_ready and only then has anything to post back. The line below changes on its own when the round trip lands — nothing here is waiting on a click.
