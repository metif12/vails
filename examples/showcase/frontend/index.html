Vails Showcase

reading platform support…

Bridge

IDLE

A JS → V → JS round trip. The panel asserts on the value that comes back, not merely on a resolved promise.

Main-thread post (U0)

IDLE

A spawned worker hands a closure back to the window thread, which emits. Arriving at all is the proof — a worker calling ctx.emit directly would be off the owning thread.

Capability gate

IDLE

A command the manifest does not grant. The panel passes when the call is refused — a rejection here is the security property working, so a resolved promise would be the failure.

Host info

IDLE

Pure V on both platforms, so this panel is a check that the service is wired rather than a check of the OS.

Clipboard

IDLE

Write, then read back, then compare — the convention ADR-0014 established for a machine-checkable service result.

Notification

IDLE

A real toast on Windows (WinRT) and a tray balloon on Linux. The command returns which mechanism actually ran.

Opener allowlist

IDLE

The checkable half is a refusal: a granted opener must not become a way to launch file://. Opening a real URL needs a browser you are watching.

Menu

IDLE

A popup menu is a modal loop with a human in it, so the window menu bar is the checkable half — it installs on the window and the choice comes back as menu:clicked.

Dialog

IDLE

A file picker is the service working. It also blocks this window until you answer — that is the platform's modal call, not a Vails choice, and it is why this panel never claims PASS on its own.

Tray

IDLE

Installs a real icon and a real menu. Verdict NEEDS YOU because the click that proves it happens in the notification area, not in this window.

Drag & drop

IDLE

Arms the window, then waits for a human to drag a file onto it. The page gets drop:files and not the DOM's drop event — that is the price of the only reachable native path (ADR-0036).
